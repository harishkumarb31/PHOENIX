# PHOENIX Security & Safety Architecture
**Zero-Trust Observability & Safe Autonomous Execution**

---

## 1. Authentication & Session Management
- **PBKDF2-HMAC-SHA256**: Passwords stored using PBKDF2 with 100,000 hashing rounds and individual cryptographic salts.
- **JWT (JSON Web Tokens)**: Cryptographically signed tokens (HS256) with strict expiry and payload validation.
- **CORS Protection**: Explicit allowlist configuration restricting origin access.

---

## 2. Role-Based Access Control (RBAC)

| Role | Hierarchy Level | Capabilities |
| :--- | :---: | :--- |
| **Super Administrator** (`super_admin`) | Level 4 | Full system governance, user provisioning, global policy config, target deregistration. |
| **Infrastructure Administrator** (`infra_admin`) | Level 3 | Register/modify monitoring targets, configure alert rules, evaluate incident queues. |
| **SRE / Operator** (`sre_operator`) | Level 2 | Telemetry observation, incident triage, RCA workbench, plan formulation, playbook execution. |
| **Viewer** (`viewer`) | Level 1 | Read-only dashboards, metric exploration, incident review, analytics report generation. |

All administrative and mutating API routes are enforced via backend dependencies (`require_role(...)`). Client-side role visibility checks are never relied upon for security boundaries.

---

## 3. Autonomous Self-Healing Safety Model
- **Non-Invasive by Default**: Default execution mode is virtual sandbox simulation.
- **No Arbitrary Shell Execution**: PHOENIX strictly rejects open-ended shell command execution generated by LLMs or external inputs.
- **Playbook Allowlisting**: Only predefined, statically audited playbooks from the verified catalog may be triggered.
- **Mandatory Approval Gates**: Destructive or service-impacting remediations require explicit operator approval.
- **Rollback Preparedness**: Every formulated recovery plan defines verified rollback steps.
- **Telemetry Verification Gating**: Incidents cannot be marked resolved without quantitative proof that the affected metric vector returned within normal thresholds.
- **Immutable Audit Logging**: Every login, fault injection, plan generation, approval, execution, and verification is permanently logged to `audit_logs`.
